# BrowserInstrument VST3 — Technical Documentation & User Guide

**BrowserInstrument** is an open-source VST3 and Standalone audio plugin built with the JUCE framework. It embeds a modern web browser engine (WebKitGTK) directly inside your DAW (e.g. Bitwig Studio, Reaper, Ableton Live via wrapper, etc.), allowing you to play, route, and sample any Web Audio & Web MIDI instrument (such as [YPC2000](https://ypc2000.fun/), AcidMachine, Roland 50 Studio, WebSynths, Strudel, etc.) as if it were a native channel instrument.

---

## 1. Audio Architecture & Ultra-Low Latency

### 1.1 Native Audio Flow & Speaker Isolation (Zero Leakage)
On Linux (PipeWire / PulseAudio), the plugin creates and maintains an isolated virtual null sink:
- **Sink Name**: `BrowserInstrumentSink` (`module-null-sink`).
- When the plugin initializes, the environment variable `PULSE_SINK=BrowserInstrumentSink` directs all audio generated by WebKitGTK / GStreamer (Web Audio API, HTML5 `<audio>` and `<video>`, YouTube iframes) into this virtual sink.
- **Zero Leakage**: Web audio is never played through system physical speakers or ALSA directly. It is captured strictly within the DAW track channel strip.

### 1.2 PulseAudio Real-Time Capture
The background C++ `PulseAudioCaptureThread`:
1. Connects directly to `BrowserInstrumentSink.monitor` via `libpulse-simple` C APIs with real-time thread priority (`juce::Thread::Priority::highest`).
2. Configures a 32-bit float PCM stream (`PA_SAMPLE_FLOAT32LE`) matching the DAW sample rate (e.g., 44.1 kHz, 48 kHz, 96 kHz).
3. Utilizes ultra-low latency fragment sizing (`PULSE_LATENCY_MSEC=5`) to ensure round-trip response under 10 ms.
4. Streams continuous float PCM directly into an internal lock-free ring buffer FIFO.

### 1.3 Zero-Latency Backlog Enforcement
To ensure instantaneous pad strikes and MIDI playback responsiveness:
- When the DAW stops, old audio buffers are flushed so that resuming playback begins with zero backlog.
- Dynamic buffer cushion controls (`64 smp` to `8192 smp`) allow tailoring between absolute zero latency (< 1.5 ms) and safety buffer headroom on heavy sessions.
- Non-blocking socket writes (`MSG_DONTWAIT | MSG_NOSIGNAL`) and non-blocking mutex locks (`std::try_to_lock`) ensure the DAW's real-time `processBlock()` thread never stalls or freezes.

## 2. Web MIDI & DAW Synchronization

### 2.1 Web MIDI API Emulation
Upon page load (`document_start`), the plugin injects a specialized bridge script that:
1. Implements standard `navigator.requestMIDIAccess()`.
2. Exposes virtual MIDI ports (`BrowserInstrument In` and `BrowserInstrument Out`).
3. Translates DAW incoming MIDI notes and CC events into standard `MIDIMessageEvent` instances for web apps.
4. For MPC-style samplers (e.g. YPC2000) that listen to keyboard keys, it simultaneously emits matching `KeyboardEvent` events mapped to trigger pads (`1..9`, `0`, `Q..P`, `A..L`, `Z..M`).

### 2.2 Universal Background DAW Transport Sync
- **MIDI Start (`0xFA`)**: Dispatched automatically when DAW playback begins.
- **MIDI Stop (`0xFC`)**: Dispatched automatically when DAW playback stops.
- **BPM Sync**: Real-time project tempo updates via `window.__JUCE_BRIDGE__.setBpm(bpm)`.
- Automatic evaluation & stop support for live-coding environments like Strudel (`strudelMirror.evaluate()` / `stop()`).

### 2.3 Resampling DAW Audio (Audio In)
The bridge emulates `navigator.mediaDevices.getUserMedia({ audio: true })`:
- Routes live DAW track audio directly into web sampler recording inputs (e.g., capturing microphone or synth input into YPC2000 pads).
- Guarded by non-blocking transmission to guarantee realtime safety.

## 3. User Interface & Controls

### 3.1 Top Navigation Bar
- **Navigation Buttons**: `◀ Back`, `▶ Forward`, `⟳ Refresh Page`, `⌂ Home` (loads default instrument, e.g. YPC2000).
- **URL Bar**: Enter any web app URL (e.g. `https://ypc2000.fun/`, `https://acid-machine.com/`, `https://strudel.cc/`, `localhost:3000`).
- **Buffer Selector**: Choose jitter cushion latency from `64 smp (~1.3ms)` to `8192 smp (~170ms)`.

### 3.2 Bottom Telemetry & Status Bar
- **Status Dot**: Green indicator confirming DAW channel routing and WebSocket connection status.
- **MIDI IN / OUT LEDs**: Cyan and amber activity flashes showing incoming DAW MIDI and outgoing web sequencer MIDI.
- **Peak dB Meter**: Real-time audio output meter and numerical decibel readout.
- **Flush Button**: Instantly resets and flushes audio FIFO buffers.
- **Gain Slider**: Adjusts output volume before entering the DAW mixer track.

## 4. Installation & Requirements

### System Requirements
- **OS**: Linux x86_64 (Ubuntu 22.04+, Debian 12+, Arch Linux, Fedora).
- **Sound Server**: PipeWire (with `pipewire-pulse`) or PulseAudio.
- **DAW**: Bitwig Studio 5+, Reaper, or any VST3-compatible host.
- **Dependencies**: `libwebkit2gtk-4.1`, `libpulse0`.

### Manual Installation
```bash
# Extract Release archive
tar -xzf BrowserInstrument-Linux-x86_64-v1.0.1.tar.gz

# Install to user VST3 directory
mkdir -p ~/.vst3
cp -r BrowserInstrument-Linux-x86_64-v1.0.1/BrowserInstrument.vst3 ~/.vst3/
```

After copying, rescan your VST3 plugins inside your DAW.

## 5. Troubleshooting & FAQ

* **Window is blank on start?**
  Ensure `libwebkit2gtk-4.1-0` is installed on your system (`sudo apt install libwebkit2gtk-4.1-0`).
* **Audio crackling or underruns?**
  Increase the buffer cushion selector in the top bar from `256 smp` to `512 smp` or `1024 smp`.
* **Audio stops when closing editor window?**
  The browser instance is persistent and automatically retained by the AudioProcessor. Audio continues playing in the background while the window is closed.
